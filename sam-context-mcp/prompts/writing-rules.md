# Writing Rules

## Purpose
Style guide for any content written by AI agents on Sam's behalf or for Sam's context files.

## Rules

### Structure
- Lead with the main point or recommendation
- Use headers to organize sections
- Use bullet points for lists of 3+ items
- Use tables for comparisons
- Keep paragraphs to 3 sentences maximum

### Tone
- Direct and professional
- Confident but not arrogant
- Precise — avoid weasel words ("some", "various", "a number of")
- Active voice preferred

### Formatting
- **Bold** for key terms on first use
- `Code formatting` for system names, tool names, and technical identifiers
- Use markdown throughout
- No emojis unless Sam explicitly requests them

### Uncertainty
- **[Unverified]** — fact not confirmed from a primary source
- **[Inference]** — conclusion derived from reasoning, not direct evidence
- **[Assumption]** — working assumption that should be validated

### Prohibited
- "I'd be happy to..."
- "Great question!"
- "Certainly!"
- "Let me help you with that"
- "In today's fast-paced world..."
- Any decorative or filler language
- Restating the question before answering
- Unnecessary hedging or over-qualifying

### Document Updates
- When updating context files, preserve the standard section structure (Title, Purpose, Current State, Key Facts, Operating Implications, Open Questions, Update Triggers)
- Add a comment with the date and nature of the change
- Do not delete existing content without explicit instruction — mark as deprecated if outdated
